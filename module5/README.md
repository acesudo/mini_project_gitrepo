# Module 5 — Face Matching & Candidate Evaluation

## 1. Overview

Module 5 is the **decision-making core** of the face recognition attendance system. It compares live query embeddings generated by Module 4 against a gallery of registered student representations, evaluates matching thresholds, selects the best candidate, and identifies unknown individuals.

``` mermaid
flowchart TD
    A[Query Face Crop] --> B[Module 4: FaceNet Embedding<br/>512 float32, unit norm]
    B --> C[Vectorized Gallery Comparison<br/>S = E · q]
    C --> D[Identify Candidate with Max Similarity<br/>s*, C* = max(S)]
    D --> E{C* >= Threshold?<br/>Default: 0.70}
    E -->|Yes| F[Known Student<br/>is_known = True<br/>student_id = s*]
    E -->|No| G[Unknown Person<br/>is_known = False<br/>student_id = UNKNOWN]
    F --> H[Module 6: Record Attendance]
    G --> I[Do Not Record Attendance]
```

## 2. Mathematical Concepts for Students

### Why Cosine Similarity?
Since all embeddings in Module 4 are projected onto a 512-dimensional unit hypersphere ($\|v\|_2 = 1.0$), the cosine similarity between two vectors $u$ and $v$ simplifies to their **dot product**:
$$\cos(\theta) = \frac{u \cdot v}{\|u\|_2 \|v\|_2} = u \cdot v$$

### Equivalence to Euclidean Distance
For unit-normalized vectors:
$$\|u - v\|^2 = \sum_{i=1}^{512} (u_i - v_i)^2 = \|u\|^2 + \|v\|^2 - 2(u \cdot v) = 1 + 1 - 2\cos(\theta) = 2 - 2\cos(\theta)$$
$$\text{Distance} = \sqrt{2 - 2\cos(\theta)}$$

| Match Quality | Cosine Similarity | Euclidean Distance | Decision |
|---|---|---|---|
| **Identical Face** | $1.00$ | $0.00$ | Perfect Match |
| **Same Person (Minor expression/lighting difference)** | $0.75 - 0.95$ | $0.31 - 0.70$ | Accepted (Known) |
| **Threshold Boundary** | $0.70$ | $0.77$ | Accepted Cutoff |
| **Different Persons** | $< 0.40$ | $> 1.10$ | Rejected (Unknown) |
| **Orthogonal Vectors** | $0.00$ | $1.41$ | No similarity |

### Biometric Error Rates: FAR vs FRR
When choosing a matching threshold, there is a fundamental trade-off:
1. **False Acceptance Rate (FAR)**: The probability that an unauthorized or unknown person is incorrectly identified as a registered student.
2. **False Rejection Rate (FRR)**: The probability that a genuine registered student is incorrectly marked as unknown.

- **Lowering the threshold (e.g. 0.50)**: Decreases FRR (easier to pass), but increases FAR (higher risk of false attendance).
- **Raising the threshold (e.g. 0.85)**: Decreases FAR (very strict), but increases FRR (students might be rejected if lighting is imperfect).
- **Our Default (0.70)**: Balances low FAR while accommodating natural classroom lighting variations.

## 3. High-Performance Gallery Matching ($E \cdot q$)

Rather than comparing a query face against registered students in a slow Python `for` loop, Module 5 stacks all $N$ registered student embeddings into an $(N, 512)$ 2D matrix $E$.

When a face $q$ is detected:
$$S = E \cdot q = \begin{bmatrix} e_1 \\ e_2 \\ \vdots \\ e_N \end{bmatrix} \cdot q$$
This single BLAS-optimized matrix multiplication computes similarity scores against hundreds or thousands of students in less than **1 millisecond**.

## 4. Key Classes & Methods

### `MatchResult`
Dataclass representing the decision for a detected face:
- `student_id`: Identified student ID (e.g., `"CSE1025"`) or `"UNKNOWN"`.
- `confidence`: Cosine similarity score ($-1.0$ to $1.0$).
- `distance`: Euclidean distance ($\ge 0$).
- `is_known`: Boolean flag (`True` if confidence $\ge$ threshold).
- `bbox`: Bounding box `(x, y, w, h)` in the original frame.

### `FaceMatcher`
- `register_student(student_id, embedding)`: Adds a student to the gallery.
- `match_embedding(query_embedding)`: Matches a single 512-d vector against the gallery.
- `match_frame(frame)`: End-to-end multi-face recognition for an entire OpenCV camera frame.
- `draw_matches(frame, matches)`: Draws green bounding boxes for recognized students and red boxes for unknown individuals.
